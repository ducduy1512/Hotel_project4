HOTEL PROJECT 5 - HANDOVER CHECKS
================================

Peak-season surcharge update
- Peak-season rates are restricted to 0.6, 0.5, 0.4, 0.3, 0.2 and 0.1.
- The amount is additive: nightly base room price x rate. It is not a room-price multiplier.
- Booking, Pay and HoaDon persist the surcharge separately from base room and service amounts.
- Invoice total is checked as base room + peak surcharge + services.
- Existing-database migration: Hotel_Peak_Surcharge_Migration.sql. It preserves Pay amounts, invoice totals, statuses and QR history.
- Fresh database install: use Hotel_Complete.sql OR the six modular SQL files in README.md; do not run both.

- SQL test cases added for allowed rates, Booking nightly snapshot totals, Pay-to-Booking snapshot equality, Pay-to-invoice amounts and three-part invoice sums.

Before using the application
1. Back up your existing database.
2. For an existing database with the earlier peak-season snapshot columns, run Hotel_Peak_Surcharge_Migration.sql once.
3. For a fresh database, use Hotel_Complete.sql OR the modular order documented in README.md.
4. Run Hotel_TestCase.sql and confirm all *_MISMATCH / *_INVALID / *_MISSING counters are zero (except any known legacy conditions you intentionally retain).
5. Copy .env.example to .env and enter your own MySQL / authentication / payment settings.

This build keeps the eight ERD business tables and the existing support tables; it does not add new database tables.
